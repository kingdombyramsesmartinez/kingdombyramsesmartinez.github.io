Responsible Security Disclosure

Kingdom welcomes reports regarding real or potential vulnerabilities relating to this domain.

Channel

Please send reports to kingdombrandbqto@gmail.com. Do not include passwords, credentials, sensitive customer data, or unnecessary personal information.

Report Details

Please specify affected domain or URL, clear description, observed impact, minimal steps to reproduce, non-sensitive evidence, and mitigation recommendations where applicable.

Rules of Engagement

Do not disrupt services, do not alter or delete data, do not access third-party accounts, do not perform social engineering, do not use brute force methods, and do not disclose vulnerabilities publicly prior to reasonable coordinated remediation.

Response

Our commitment is to acknowledge receipt and evaluate reports. Response timeframes may vary depending on severity, evidence provided, and complexity.

Security Architecture and Hosting

This website is published on GitHub Pages as a static environment without backend databases, servers, or active user session processing.

In this hosting environment, browser protection is configured through the <meta http-equiv="Content-Security-Policy"> tag, which mitigates Cross-Site Scripting (XSS), code injection, and unauthorized resources by restricting scripts, styles, connections, and objects to legitimate origins. However, as GitHub Pages does not support edge response header modification, headers such as Strict HSTS, X-Frame-Options, Permissions-Policy, or frame-ancestors cannot be delivered directly by the host; the _headers file is reserved for a future edge migration (e.g. Cloudflare Pages).
